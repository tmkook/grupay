## 系统是怎么运转的

商户在自己的系统里创建订单，付款人打开支付页面后，系统才开始找手机干活。

完整过程只有一条主线：

1. 商户创建订单，此时还不占用任何手机。
2. 付款人打开支付页面，系统开始寻找一台合适的手机。
3. 被选中的手机自动切到产品网站，用登录好的账号完成充值下单。
4. 系统把支付链接交给付款人。
5. 付款人付款成功，订单完成；超过有效时间未付款，订单过期。

订单金额都是整数元，每天的额度按北京时间的自然日计算。

## 一台手机要做的事

一台手机想稳定接单，需要同时满足下面几点。任何一条不满足，它都不会被派单：

- App 正常运行并保持网络连接。
- 已在产品网站登录好账号，且账号没有掉登录。
- 接单开关是开启状态。
- 当前选择的产品和订单的产品一致。
- App 账号余额足够支付这一单。
- 当天的额度和同时待付款的订单数没有达到上限。

订单进来时，App 会自动切到产品页，所以建单期间手机必须停在这个页面并保持前台。如果中途退到后台或者锁屏被杀，这一单会失败，系统会交给别的手机重试。

## 第一次开始接单

1. 安装并打开 App，用账号和密码登录，服务器地址由服务方提供。
2. 第一次登录时选择一个产品，之后会自动记住。
3. 进入「站点」，在产品网站里登录要使用的账号。检测到账号后，设备会自动进入可接单状态。
4. 打开「设置 → 接单设置」，确认接单开关是开启的（新手机默认开启），需要的话同时设置日额度和同时待付款上限，然后保存。
5. 把 App 留在前台，就可以接单了。

> 接单开关是唯一需要手动控制的地方。登录、断线重连、切换产品、退到后台，都不会自动帮你开关接单。

## 接单设置

入口在 App 底部「设置 → 接单设置」，改完点「保存设置」一起生效。

| 设置项 | 作用 |
| --- | --- |
| 接单开关 | 关掉后不再接新订单，已经在进行中的订单仍要完成 |
| 设备日限额 | 这台手机当天最多接多少金额的订单，填 0 表示不限制 |
| 设备权重 | 多台手机同时可用时，权重越高越先被选中，填 0 也能接单 |
| 未完成订单上限 | 这台手机同时最多挂多少笔还没付款的订单，填 0 表示不限制 |

同一台手机同一时间只会做一笔单，不同手机之间互不影响。

设置里还有几项日常会用到的功能：

- **息屏保护**：默认关闭。开启后屏幕保持常亮，闲置一段时间变暗，点一下恢复。
- **修改密码**：修改当前 App 账号的登录密码。
- **浏览器 UA**：查看站点浏览器使用的手机型号标识。
- **消息日志**：查看最近的连接和业务记录，排查问题时有用。
- **关于**：查看版本和设备编号，也可以检查更新。

## 主页状态怎么看

主页顶部会直接告诉你这台手机现在能不能接单：

| 显示 | 含义 |
| --- | --- |
| 接单中 | 一切正常，可以接到订单 |
| 产品账号未登录 | 产品网站里没检测到账号，需要重新登录 |
| 已暂停接单 | 接单开关被关掉了 |
| 客户端版本过低 | 版本太旧，需要更新 App |
| 重新连接中 | 网络连接断开，正在自动重连 |

显示“接单中”才代表这台手机真的在参与派单。其他状态都会在下面一行说明具体原因。

## 订单会经历哪些阶段

| 阶段 | 说明 |
| --- | --- |
| 等待付款人打开页面 | 商户已建单，还没人打开支付页，不占用手机 |
| 正在下单 | 手机已经接到订单，正在产品网站完成充值下单 |
| 等待付款 | 支付链接已生成，等付款人付款 |
| 已完成 | 付款成功，订单结束 |
| 已过期 | 超过有效时间仍未付款 |
| 失败 | 下单失败或排队太久没轮到手机 |

订单的有效时间从商户建单开始算，默认 10 分钟。手机不够时，订单会按创建顺序排队，排太久会直接失败。

## 管理机器人

系统提供一个 Telegram 管理机器人，日常查数据、改配置都可以直接用手机操作，不用登录服务器。

**绑定管理员**：联系服务方获取一串绑定密钥。管理员用自己的 Telegram 私聊机器人，直接发送这串密钥即可绑定，绑定后密钥立即失效。之后输入 `/start` 打开管理菜单，输入 `/id` 可以查看自己的 Telegram 数字 ID。

| 菜单 | 能做什么 |
| --- | --- |
| 商户管理 | 查看商户列表和详情，新建商户并自动生成对接用的 AppID 和 AppKey，启用或停用商户 |
| 设备管理 | 查看每台手机是否在线、是否在接单，调整权重和日限额 |
| 订单管理 | 按订单编号或商户单号查看订单详情和过程记录，把失败的回调重新推送 |
| 账号管理 | 新建 App 账号，启用或停用，查看余额，增减余额，重置登录密码 |

常用示例：新建商户发送 `/merchant_add 商户名称`，重置账号密码发送 `/account_reset 账号编号 新密码`。

需要撤销某个管理员的权限时，联系服务方处理即可。

## 需要多少台手机

能接多少单，取决于“在线且可接单的手机数量”，而不是商户下了多少单。

有三条关键限制：

1. 一台手机同一时间只做一笔单，多台手机同时并行。
2. 每笔单通常需要几秒完成，可以粗略按每台手机每分钟 8–12 单估算。
3. **未完成订单上限**会占住手机：挂着的待付款订单达到上限后，这台手机要等有订单付款或过期，才能继续接新单。

估算方式：

```text
需要的手机数 ≈ 每分钟峰值订单量 ÷ 每台手机每分钟能做的单数
再乘以 1.3–1.5 的余量，应付掉线、暂停、更新和失败重排
```

例如峰值每分钟 60 单，每台手机每分钟约 10 单，理论需要 6 台，按 1.5 倍余量准备 9 台比较稳妥。

下面这些情况会让“看起来在线”的手机实际接不了单：

- 手机离线、App 被系统清理、网络不稳定
- 产品账号掉登录
- 接单开关被关闭，或者日额度、未完成上限已满
- App 账号余额不足，付不起订单金额
- App 版本低于要求，需要更新

## 常见问题

| 现象 | 先检查什么 |
| --- | --- |
| 主页一直显示“产品账号未登录” | 产品网站是否停在充值页、账号是否还登录着，必要时重新登录 |
| 显示“已暂停接单” | 进入接单设置打开开关并保存 |
| 订单派到了但下单失败 | App 是否在前台、产品网站能否正常下单、账号登录是否失效 |
| 提示产品登录已失效 | 重新在产品网站登录账号，设备恢复后会自动继续接单 |
| 长时间没有新订单 | 手机是否在线、产品是否一致、余额是否充足、日额度或未完成上限是否已满 |
| 订单显示已过期 | 付款人超时未付，或手机不足导致排队过久 |
| 商户收不到回调 | 检查商户回调地址能否访问、是否正常返回，也可以在机器人里重新推送 |
